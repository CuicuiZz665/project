# PRD：角色模块权限、数据可见范围与客户归属管理

- 版本：v0.8（草案 · 按"总监 / 客服"两级角色全文整理）
- 日期：2026-09-20
- 状态：待评审
- 适用项目：IB_admin 静态原型（React + antd，浏览器直开 `index.html`，无构建）

---

## 1. 背景与目标

后台目前"所有人看到同一个菜单、同一份数据"，无法体现组织层级。本 PRD 把三条规则产品化：

1. **功能权限**：不同角色登录后看到的模块不同（如总监可见全部 6 个模块，客服只可见其中 4 个）。
2. **数据权限**：账号只能看到自己组织范围内的数据——我下面的全部人员、我下面客服名下的代理、我下面客服名下的直接客户。
3. **客户归属管理**：新注册客户分配客服后才对客服可见；已归属客户可在客服之间划转；分配与划转全部留痕可查。

组织层级只有两级角色：**总监（第一级，根）→ 客服（第二级）**。

一句话边界：**本 PRD 只解决"谁能看什么、客户归谁、变更有没有记录"，不新增业务模块。**

## 2. 名词定义

| 名词 | 定义 | 落点 |
| --- | --- | --- |
| 角色 | 岗位模板，决定可见模块（功能权限）与数据范围类型。如：总监、customer service、风控专员 | 角色管理设置 |
| 账号（用户） | 一个登录身份，绑定一个角色、挂在组织树一个节点上 | 用户设置管理 |
| 组织节点 | 组织树的节点，仅两层：总监（根）→ 客服 | 用户设置管理维护 |
| 数据范围 | 账号能看到的组织口径：全部 / 本部门及以下 / 仅本人 / 自定义 | 角色管理设置配置 |
| 客户归属 | 客户挂靠的关系：所属客服（唯一归属字段） | 客户列表维护 |
| 分配 | 未分配客户 → 指定客服（首次归属） | 客户列表 |
| 划转 | 已归属客户 → 从客服 A 换到客服 B | 客户列表 |

## 4. 功能需求详述

### 4.A 模块可见性（功能权限）

**规则**

1. 权限树与侧边栏菜单同构：一级 = 模块（客户管理、代理关系管理、积分、活动管理、投递管理、系统管理），二级 = 页面（客户列表、数据概览……）。勾选粒度到二级页面；勾选一级视为勾选全部二级。
2. 侧边栏按当前登录账号 → 角色 → `permissions` 过滤：整组无任何已勾选二级页面的模块整体隐藏；仅保留有权限的叶子页面。禁用态占位项（徽章、优惠券、充值提现）不参与。
3. 无权限页面不可直达：切换账号后若当前停留页面不在新权限内，自动回落到第一个有权限的页面。
4. 菜单只做显示过滤，不改变页面内部逻辑（页面内部数据仍由数据权限控制）。

**示例配置（对应"总监 6 个模块、客服 4 个模块"）**

| 角色 | 可见模块 | 数据范围 |
| --- | --- | --- |
| Root / 总监（Andy） | 全部 6 个模块 | 全部数据 |
| customer service（QQ / cs1 / cs2） | 4 个：客户管理、积分、活动管理、投递管理 | 本部门及以下 |
| 风控专员（Rita） | 1 个：客户管理（仅客户列表） | 自定义（svc-qq、svc-cs2） |

### 4.B 数据可见性（数据权限）

**规则**

| 数据范围类型 | 可见对象 |
| --- | --- |
| 全部数据（all） | 组织树全体 |
| 本部门及以下（dept） | 自己节点 + 全部下级节点的子树 |
| 仅本人（self） | 只看自己节点名下 |
| 自定义（custom） | 勾选的多个节点的子树并集 |

两级架构下的实际口径：总监看全局（"全部数据"），客服看自己名下（"仅本人"）。"本部门及以下 / 自定义"保留在机制里备用。

**三类可见数据 = "我下面的人"**

1. **下面的人员**：我范围内所有客服（含我本人，总监视角为全部客服）。
2. **下面的代理**：归属我范围内客服名下的代理。
3. **下面的直接客户**：`service` 落在我范围内客服名下的客户。

**未分配客户规则**

- `service` 为空的客户 = 未分配，**只有总监可见**，任何客服不可见。
- 客户列表在总监视角提供"所属客服 = 未分配"筛选，并在未分配数量 > 0 时于工具栏展示"待分配 N 人"提示，点击即应用该筛选。

**下钻视角**：总监可在自己范围内临时切换到某个客服的视角（沿用现有 ScopeSwitcher），不突破数据范围。

### 4.C 分配客服（单个 + 批量）

**定义**：未分配 → 指定客服（首次归属）。本期不做自动分配：注册后停在"未分配"，由总监在客户列表手动分配。

| 项 | 内容 |
| --- | --- |
| 入口 | 客户列表工具栏"分配客服"：未勾选行 = 单个模式（输入客户编号）；勾选 N 行 = 批量模式 |
| 行选择 | 表格新增复选框列，仅对有操作权限的账号显示；表头全选按当前筛选结果生效 |
| 单个表单 | 客户编号（必填，自动匹配显示当前归属）、目标客服（必选，限启用状态） |
| 批量表单 | 已选客户摘要（N 个，含当前归属分布）、目标客服（必选，限启用状态） |
| 校验 | 客户编号必须存在；目标客服 ≠ 当前客服；目标客服账号须为启用状态；批量时逐条校验，不整体阻断 |
| 操作权限 | 仅总监。客服不显示分配 / 划转按钮与行选择列，也看不到未分配客户 |
| 生效 | 写入客户 `service`；每个客户各写入一条归属变更记录（动作 = 分配） |
| 结果反馈 | 单个：成功 toast；批量：结果摘要（成功 N / 跳过 M，跳过原因如"已是该客服"） |

典型流程（总监视角）：筛选"所属客服 = 未分配" → 表头全选或勾选 → 批量分配 → 选目标客服 → 确认。

### 4.D 划转客服（单个 + 批量）

**定义**：已归属 → 从客服 A 换绑到客服 B。

| 项 | 内容 |
| --- | --- |
| 入口 | 客户列表工具栏"划转用户"：未勾选行 = 单个模式；勾选 N 行 = 批量模式 |
| 单个表单 | 客户编号（必填，自动匹配并只读显示当前客服）、原客服（只读回显）、新客服（必选，≠ 原客服）、划转原因（**必填**，文本 ≤ 200 字） |
| 批量表单 | 已选客户摘要（N 个，含原客服分布）、新客服（必选）、划转原因（**必填**，≤ 200 字，整批共用） |
| 校验 | 同 4.C；另要求客户当前已有归属（未分配客户走"分配"）；批量时"新客服 = 当前客服"的客户自动跳过，不整体阻断 |
| 操作权限 | 仅总监（同 4.C） |
| 生效 | ① `service` 改为新客服，归属即完成切换；② 每个客户各写入一条归属变更记录（动作 = 划转，含原因） |
| 结果反馈 | 批量：结果摘要（成功 N / 跳过 M 及原因） |
| 可见性联动 | 划出方立即失去该客户可见性；划入方立即获得 |

### 4.E 归属变更记录

| 项 | 内容 |
| --- | --- |
| 入口 | 客户列表页顶部 Tab：「客户列表」/「归属变更记录」 |
| 记录字段 | 记录ID、时间(GMT+8)、操作人（账号 + 角色）、动作（分配 / 划转）、客户编号、客户昵称、原客服、新客服、划转原因、操作结果 |
| 筛选 | 客户编号、动作类型、原客服 / 新客服、时间区间 |
| 数据权限 | 与客户列表同口径：只能看到自己范围内客户的记录（总监看全部） |
| 数据结构 | `mock-data.js` 新增 `ownershipRecords` 数组；分配、划转动作各写一条 |

## 5. 页面落点设计

三个页面各管一件事，职责按"改的是什么"划分：

| 页面 | 管什么 | 一句话职责 | 本期相关改动 |
| --- | --- | --- | --- |
| **角色管理设置** | 岗位模板 | "这个角色能看哪些模块、用什么数据范围" —— 改模板，影响所有该角色账号 | 权限树对齐菜单；示例角色权限更新 |
| **用户设置管理** | 账号与组织 | "这个账号是谁、什么角色、挂在组织树哪个节点、上级是谁" —— 换上级 = 组织调动 | 组织类型仅 总监 / 客服 两项 |
| **客户列表** | 客户归属 + 留痕 | "这个客户归哪个客服" —— 分配、划转、变更记录都是客户维度的事 | 划转弹窗落地；记录 Tab；待分配提示；目标客服校验 |

**设计逻辑（判定原则）**：

1. 操作落在**操作对象所在的列表页**：客户的归属操作在客户列表；人员的组织调整在用户设置；模板调整在角色设置。
2. 角色设置只改"规则"，用户设置只改"人"，客户列表只改"业务归属"，三者互不越界。
3. 记录跟着主体走：归属变更记录的主体是客户 → 放客户列表下，不放进系统管理。

## 6. 验收标准

1. 总监（Andy）登录：侧边栏可见全部 6 个模块；客服（QQ）登录：仅见示例中的 4 个模块，无代理关系管理与系统管理。
2. 风控专员（Rita）登录：仅见客户管理 → 客户列表；数据只见自定义范围内客户。
3. 客服 cs1 登录客户列表：只见归属 cs1 的客户；看不到其他客服的客户，也看不到未分配客户。
4. 新客户"张三"注册后未分配：cs1 看不见张三；总监可见且能筛出"未分配"，工具栏显示待分配人数。
5. 总监把张三分配给 cs1：cs1 立即可见张三；归属变更记录新增一条"分配"。
6. 总监把张三从 cs1 划转给 cs2（填原因）：cs1 不可见、cs2 可见；记录新增一条"划转"，含原/新客服与原因。
7. 划转弹窗校验：新客服 = 原客服时阻断；未分配客户走划转时阻断并引导使用分配；原因未填时阻断。
8. 切换登录账号后，若停留页面不在新角色权限内，自动回落到第一个有权限页面，不出现空白页。
9. 归属变更记录受数据权限控制：cs1 只能看到自己范围内客户的记录。
10. 客服登录客户列表：不显示"分配客服 / 划转用户"按钮，表格无复选框列。
11. 总监筛"未分配"后勾选 3 个客户批量分配给 cs1：生成 3 条"分配"记录，cs1 可见全部 3 个客户。
12. 批量划转含"已是目标客服"的客户：结果摘要显示成功 / 跳过数量，跳过者归属不变、不生成记录。
