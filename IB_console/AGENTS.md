# AGENTS.md

Gin Partner 控制台（对应线上系统 `https://partner.ginx.io`，深色主题）的静态原型项目。与同级目录的 `IB_admin`（管理后台）是两个独立项目，互不共享文件；`vendor/` 是从 IB_admin 复制的一份独立副本。功能逻辑说明见根目录 `PRD-合伙计划功能.md`（按页面组织，含字段/交互/边界）。

直接从项目根目录用浏览器打开 `index.html` 即可预览（本地服务器：`python3 -m http.server 8642` → http://127.0.0.1:8642/index.html）。不使用 Node、npm、打包器或框架运行时。

## Startup Chain

```text
index.html
`-- js/bootstrap.js 按序加载
    vendor: react → react-dom → dayjs → antd
    app:    namespace.js → mock-data.js → overview-page.js → partner-page.js → direct-customers-page.js → app-shell.js
            `-- app.shell.init() 渲染 <App/>
```

新增 JS 文件时，先确认它依赖的 `window.IBApp` 成员，再把它插入 `js/bootstrap.js` 的正确位置。不使用 ES module import。

- 数据表格列**统一左对齐**（数字列不做右对齐，操作列也左对齐；数字仍用等宽字体 `ib-num`）

## 约定

- 每个 JS 文件一个 IIFE，注册到 `window.IBApp`（如 `app.XxxPage = ...`）。
- 总览页为纯自定义 DOM/SVG（保证与截图像素级一致）；后续新页面可按需使用 antd 组件。
- 页面级样式写入对应的 `css/<page>.css`，并在 `index.html` 引入；外壳样式只在 `layout.css`。
- 业务 mock 数据统一放 `js/mock-data.js`，不要散落在页面组件里。
- 菜单与路由：`mockData.menus` 的 key 即 hash 路由（`#/overview` 等）；未实现的页面渲染占位视图。

## 合伙人功能说明（一页两区重构）

**身份模型**：页面按「计划」和「人」两个维度组织。上区一行 = 一个分佣比例（比例 + 专属邀请码）；下区一行 = 一个人（直客或子代理）。子代理 = 绑定了固定分佣比例的人（经邀请链接注册，或由直客「设为合伙人」转化）。直客明细页保持原样不动，其直客数据与下区同源（同 UID）：转化后自动从直客明细消失、解除后恢复（沿用 convertedUids 机制）。

**两层比例规则**：经链接注册的人在注册那一刻复制当时的计划比例作为个人固定比例；分佣比例创建后不可修改（无编辑入口）；按人调整只能走子代理行的「修改固定返佣比例」，调整过的行/抽屉显示「已调整」标记（rateOverridden）。分佣比例可「作废」（确认窗）：作废后状态列变「失效」（种子 plan-06 预置一条失效示例），操作列显示 — 不可再作废，专属邀请链接不再绑定该比例；已注册成员注册时复制的固定比例不受影响；新建比例默认「正常」。

- 上区「分佣比例」：列 = 计划名称 / **Web地址 / Miniapp地址**（两个独立列，分别缩略展示 `https://…码` 与 `https://t.me/…码`，邀请码完整露出；悬停 title 显示各自完整链接 `https://www.ginx.io/?invitation_code=码` / `https://t.me/ginfit_bot?start=码`，点击分别复制，1.2s 变绿互不影响；列 key `web`/`miniapp` 与 `partnerForm.inviteLinks[].key` 对应）/ 合约分佣比例 / 有效期（留空=永久）/ 注册人数（橙色可点，**当前绑定口径**，解除后自动减员）/ 状态（正常=绿徽章、失效=灰徽章，样式复用 `ib-dc-status`）/ 操作（正常行「作废」→ 确认窗）；头部右侧 = **状态筛选**（「状态」标签 + 下拉 全部/正常/失效，位于搜索框左侧，`ib-status-select` 深色下拉同 7D 配色）+ 搜索框（名称/比例/地址模糊匹配，兼配邀请码与两条完整链接，比例兼容带 % 输入，即时过滤；与状态筛选叠加过滤）+「增加返佣比例」；底部 5 条/页分页。
- 注册人数 → 抽屉：标题「邀请码 xxx · 注册客户 N 人」+ 计划摘要；顶部 4 项汇总（注册人数/活跃客户/累计交易量/累计返佣）；表格（UID/昵称/注册时间/状态/交易量/返佣/当前生效比例+已调整标记）；搜索（UID/昵称）+ 分页；Esc/遮罩/✕ 关闭。
- 下区「直客与子代理」：标题行右侧 = 直客/子代理标签切换（胶囊分段，选中态 #3A2410 底 + 橙字，默认直客）+ 单搜索框（UID/昵称模糊匹配，输入即过滤，带 ✕ 清除），与上区头部布局同款；无「人员类型」列与「全部」混合视图，列随标签切换：直客 = UID/昵称/注册时间/累计交易量/当前生效比例（—）；子代理 = UID/昵称/注册时间/累计交易量/**累计返佣**/当前生效比例/**所属邀请码**（链接注册显示码，转化显示 —）；无用户名列。
- 操作列（最末）：直客行 =「设为合伙人」小弹窗（预填昵称只读 + 独立比例，**不生成邀请码、不关联计划**，保存即变子代理）；子代理行 =「修改比例」（弹窗显示当前比例 + 新比例）+「解除」（确认窗后降回直客，原直客转化的会回到直客明细）。
- 「增加返佣比例」弹窗：合伙计划名称/合约分佣比例（各占一半）+ 时间限制（留空=永久），无邀请码字段（邀请码保存时后台自动生成，完成态展示）；7 个比例仍在「更多分佣比例设置」折叠区（暂不生效提示条，隐藏区报错自动展开）。比例按百分比数字直接填写（88 = 88%，失焦四舍五入，逗号兼容小数点，0~100）。
- 新建保存后进「添加成功」完成态：展示本比例 Web 与 Miniapp 两条专属邀请链接（`https://www.ginx.io/?invitation_code=码` 与 `https://t.me/ginfit_bot?start=码`），各自带「复制链接」按钮（1.5s「已复制」，独立变绿）+ 说明，「完成」关闭。链接配置在 `mockData.partnerForm.inviteLinks`（key/tag/label/baseUrl/shortHead），与总览页默认跟踪链接的字段口径一致。
- 数据为内存态（`app.partnerStore`，useSyncExternalStore）：plans（6 条种子）+ people（26 子代理 + 12 直客派生自 directCustomers.rows），新增比例插顶部，注册人数由 people 动态计算。

## 验证

无自动化测试（本机无 node，语法检查可用 `osascript -l JavaScript` 的 `new Function(code)` 完成）。每次改动后：浏览器打开 `index.html`，检查控制台无脚本错误；点击侧边菜单确认路由与高亮；对照线上截图检查总览页各模块。若未做浏览器验证，需说明只做了静态检查。**改 JS 后必须同步 bump `js/bootstrap.js` 的 `appVersion`**（业务脚本经 `?v=appVersion` 加载，不 bump 会命中浏览器缓存跑旧代码；CSS 版本号在 `index.html` 的 link 上，同理需 bump）。
